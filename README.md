# WB Seller Audit

Инструмент для восстановления истории продаж продавца Wildberries/MPStats и предварительного налогового аудита.

## Что делает MVP

- Chrome Extension (Manifest V3) умеет работать в двух режимах:
  - бесплатный WB public — текущий каталог продавца напрямую из публичного каталога Wildberries;
  - MPStats capture — перехват JSON/XHR/fetch из уже открытого пользователем MPStats без хранения логина/пароля.
- Backend на FastAPI нормализует найденные записи продаж.
- Считает накопительный доход, помесячные обороты и rolling-окна по 3 месяца, когда источник действительно содержит исторические продажи.
- Ищет первую продажу гетр/гамаш как кандидата на маркируемый товар.
- Ищет дату пересечения лимита НПД 2,4 млн ₽.
- Оценивает расходы маркетплейса по задаваемому коэффициенту.
- DeepSeek-классификатор подключен как отдельный слой для смысловой классификации SKU; налоговая математика остается детерминированной.

Все результаты являются предварительным аудитом. Публичные данные WB и MPStats используются для реконструкции; финальные суммы нужно сверять с официальными отчетами WB/Ozon и документами ФНС.

Первый тестовый кейс: seller `739228`, период с `2025-03-01`.

## Chrome Extension

1. Скачайте/клонируйте репозиторий.
2. Откройте `chrome://extensions`.
3. Включите «Режим разработчика».
4. Нажмите «Загрузить распакованное расширение».
5. Выберите каталог `extension/`.
6. Введите Seller ID.

### Бесплатный режим без MPStats

Нажмите **«Аудит WB без MPStats»**. Расширение само проходит страницы публичного каталога продавца через `catalog.wb.ru` из вашего Chrome и отправляет ответы backend'у для нормализации.

Этот режим даёт:

- текущий ассортимент;
- nmId, бренд и продавца;
- публичные цены;
- публичные остатки, когда WB их отдаёт;
- рейтинг/отзывы, когда они есть в ответе;
- кандидатов на маркируемый товар по названию.

Важно: публичный каталог WB **не содержит историческую выручку и продажи по датам**. Поэтому бесплатный режим не вычисляет дату превышения НПД, первую историческую продажу товара или оборот за 2025/2026. Он используется как бесплатный слой текущего каталога и для подготовки списка SKU.

### MPStats capture

Если у пользователя уже есть доступ к нужным страницам MPStats:

1. Откройте MPStats и нужные страницы продавца.
2. Нажмите «Включить перехват MPStats».
3. Пройдите по страницам с историей.
4. Нажмите «Анализ MPStats».

Перехват по умолчанию выключен. Расширение хранит последние 100 JSON-ответов MPStats в `chrome.storage.local`. Кнопка JSON позволяет выгрузить сырые captures для отладки адаптера.

## API

### `POST /api/v1/analyze`

Принимает уже нормализованные исторические продажи.

### `POST /api/v1/captures/analyze`

Принимает сырые captures расширения, пытается найти массивы продаж, нормализует их и строит исторический аудит.

### `POST /api/v1/sources/wb-public/analyze`

Принимает страницы публичного каталога WB:

```json
{
  "seller_id": 739228,
  "pages": [
    {"data": {"products": []}}
  ]
}
```

Возвращает текущий snapshot продавца и явные capabilities источника. Для WB public:

- `current_catalog=true`
- `historical_sales=false`
- `historical_revenue=false`
- `tax_dates=false`

Backend намеренно не превращает остатки, отзывы или текущие цены в выдуманную историческую выручку.

## DeepSeek

Поддерживаются переменные окружения:

- `DEEPSEEK_API_KEY`
- `DEEPSEEK_BASE_URL` (по умолчанию `https://api.deepseek.com`)
- `DEEPSEEK_MODEL` (по умолчанию `deepseek-chat`)

LLM не должен считать налоги и не является источником правовых правил. Его задача — только классификация товара/названия с confidence.

## Ограничения MVP

- WB public — недокументированный buyer endpoint; его контракт может измениться.
- WB public даёт текущий каталог, но не заменяет исторический источник продаж.
- Формат внутренних API MPStats определяется эвристически. После первого реального capture адаптер нужно закрепить под фактический контракт API.
- Расходы по коэффициенту — оценка, а не первичка.
- Кандидат маркируемого товара по названию не заменяет ОКПД2/ТН ВЭД.
- Финальный налоговый расчет не включен в MVP намеренно: сначала фиксируем надежный импорт данных и контрольные даты.
